# Shuffle Modes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a three-state shuffle button (off / within library / across libraries) that changes what `⏭` and auto-advance pick next: queue first with a random pop, then a random file in the configured scope. State persists in `ui_state`.

**Architecture:** Two new `LibraryDB` helpers do the random selection (one scoped to a `library_id`, one across all libraries). `QueueModel.take_random()` pops a random queue item. `MainWindow._play_next` branches on `self._shuffle_mode`. A new cycle-style toolbar button in the transport bar drives the state.

**Tech Stack:** Python 3.14, PyQt6, libVLC via `python3-vlc`, SQLite, pytest.

Spec: [`docs/superpowers/specs/2026-05-14-shuffle-design.md`](../specs/2026-05-14-shuffle-design.md).

```python
def random_file_in_library(self, library_id: int,
                           exclude_id: int | None = None) -> FileRow | None:
    cols = """id, library_id, path, parent_dir, filename, ext, size, mtime, duration,
              title, year, series, season, episode, artist, album, track"""
    if exclude_id is None:
        sql = f"""SELECT {cols} FROM files
                  WHERE library_id=?
                  ORDER BY RANDOM() LIMIT 1"""
        args: tuple = (library_id,)
    else:
        sql = f"""SELECT {cols} FROM files
                  WHERE library_id=? AND id != ?
                  ORDER BY RANDOM() LIMIT 1"""
        args = (library_id, exclude_id)
    row = self.conn.execute(sql, args).fetchone()
    return FileRow(*row) if row else None

def random_file_anywhere(self, exclude_id: int | None = None) -> FileRow | None:
    cols = """id, library_id, path, parent_dir, filename, ext, size, mtime, duration,
              title, year, series, season, episode, artist, album, track"""
    if exclude_id is None:
        sql = f"""SELECT {cols} FROM files
                  WHERE library_id IS NOT NULL
                  ORDER BY RANDOM() LIMIT 1"""
        args: tuple = ()
    else:
        sql = f"""SELECT {cols} FROM files
                  WHERE library_id IS NOT NULL AND id != ?
                  ORDER BY RANDOM() LIMIT 1"""
        args = (exclude_id,)
    row = self.conn.execute(sql, args).fetchone()
    return FileRow(*row) if row else None
```

```python
def take_random(self) -> Optional[FileRow]:
    """Pop and return a random file from the queue, or None if empty."""
    import random
    if not self._files:
        return None
    idx = random.randrange(len(self._files))
    f = self._files.pop(idx)
    self._rebuild()
    return f
```

The `import random` lives inside the method on purpose — it's only used here, and avoids putting `random` in the module's import list when most callers don't need it.

```python
def _play_next(self):
    """Transport ⏭: respect shuffle mode (off / within / between)."""
    f = self._take_next_for_mode()
    if f is None:
        return
    self._play(f)

def _take_next_for_mode(self):
    """Return the next FileRow to play based on self._shuffle_mode, or None."""
    if self._shuffle_mode == "off":
        f = self.queue_model.take_next()
        self._persist_queue()
        if f:
            return f
        cur = self.current_file
        if cur is None or cur.library_id is None:
            return None
        return self.db.next_file_in_folder(cur.library_id, cur.parent_dir, cur.filename)

    # Shuffle on: random pop from queue first.
    f = self.queue_model.take_random()
    self._persist_queue()
    if f:
        return f
    cur = self.current_file
    if cur is None:
        return None
    if self._shuffle_mode == "within":
        if cur.library_id is None:
            return None
        return self.db.random_file_in_library(cur.library_id, exclude_id=cur.id)
    if self._shuffle_mode == "between":
        return self.db.random_file_anywhere(exclude_id=cur.id)
    return None
```

```python
def _cycle_shuffle(self):
```

## Self-review notes

- **Spec coverage:** every section of the spec maps to a task: DB helpers (Task 1), `take_random` (Task 2), `_take_next_for_mode` and `_play_next` refactor (Task 3), button + cycle + persistence (Task 4).
- **Type consistency:** `_shuffle_mode` is `str` everywhere. `random_file_in_library` and `random_file_anywhere` have matching `exclude_id: int | None = None` signatures.
- **Auto-advance** in `_on_tick` already calls `_play_next` (per the previous next/prev feature), so shuffle behavior flows through track-end events automatically without extra wiring.
- **Stale state if a library is deleted while shuffle is on:** `current_file.library_id` would still be valid (we don't null it on delete; `_play(_)` set it from a live row). After a delete, `_play_next` in `within` mode could try `random_file_in_library` on a now-deleted library — query returns no row, no-op. Acceptable.
